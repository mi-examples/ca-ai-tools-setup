Sign Up Form

A public page where an external user requests access to a job site. No login, protected by CAPTCHA, and every submission becomes a row in the Sign Up Form dataset that the Approval Page reads.

Fields

Field Behaviour
Full name Required.
Email address Required and format-checked. A work email is expected.
Project Number Prefilled and locked when the link carries it (…/p/signup-form/501200); otherwise a dropdown from the Jobs entity.
Company / organization Shown only for roles flagged Require Company Selection = Y. Options come from the Companies entity filtered to the chosen Project Number; a single match is selected and locked. Changing the Project Number clears it.
  • Request Access stays disabled until every visible field is valid and the CAPTCHA is solved. Values are trimmed, and blank-only entries do not count as filled.
  • On success one row is appended with status = Pending, date as the submission time in Unix seconds, plus role, full_name, email and job_id.

Notifications

Two different emails are involved, and the form itself sends neither. Metric Insights has no instant-notification trigger, so approvers are notified by a poll assembled from three pieces — a flag column, a burst, and a custom script that decides whether to send.

  1. The dataset carries a notified flag — the Sign Up Form dataset has an extra notified column (Y or empty) marking the rows approvers have already been told about.
  2. A custom script decides, every 10 minutes — notify-approver runs on an enabled 10-minute Notification Schedule. Each run:
    • reads the rows — GET api/dataset_data?dataset={datasetId};
    • if no row is pending with notified ≠ Y, reports No new requests and sends nothing;
    • otherwise sends the burst now — PUT api/burst/id/{burstId} with {"call":"send","send_to":"all"}.

Prerequisites for the notification chain

CUSTOM_SCRIPT_ENABLED = Y and the image-generator service running. PRIV_CREATE_HIGH_FREQUENCY_SCHEDULES for the sub-hourly schedule. Working outbound mail (SEND_MAIL_* system variables) and at least one burst subscriber.

Known constraint

Keep the burst's element filtered to status = pending rather than "not yet notified": rows are flagged as soon as the send is triggered while burst rendering is asynchronous, so a "not notified" filter can render an empty email.

Repointing an entity

Companies can be sourced from a governed warehouse view (dim_company_v) by repointing the entity's SQL, as long as the projected column names stay the same.
